# Reporting security issues

[Français](SECURITY.fr.md)

Please do not publish credentials, private datasets, or exploit instructions in a public issue. If GitHub private vulnerability reporting is enabled for this repository, use the repository's **Security → Report a vulnerability** entry. If it is unavailable, open a public issue asking the maintainer to enable a private reporting channel, without including exploit details.

For a private report, include the affected revision, a minimal synthetic reproduction, expected/actual behavior, and the impact you observed. No response-time commitment or support window is promised here. General bugs without sensitive impact belong in the normal issue tracker.

Treat downloaded data and packages as untrusted. Preserve manifests and source licenses, use appropriate local file permissions, and never run import tests against production databases.
