# Signaler une vulnérabilité

[English](SECURITY.md)

Ne publiez pas d'identifiants de connexion, de jeux de données privés ni de procédure d'exploitation dans une issue publique. Si le signalement privé GitHub est activé pour ce dépôt, utilisez **Security → Report a vulnerability**. S'il ne l'est pas, ouvrez une issue demandant au mainteneur d'activer un canal privé, sans inclure les détails d'exploitation.

Dans le rapport privé, indiquez la révision concernée, une reproduction fictive minimale, le résultat attendu/observé et l'impact constaté. Aucun délai de réponse ni période de support n'est promis ici. Les bugs ordinaires sans impact sensible passent par les issues habituelles.

Traitez données téléchargées et paquets comme non fiables. Conservez manifestes et licences, utilisez des permissions locales adaptées et ne lancez jamais des tests d'import sur une base de production.
